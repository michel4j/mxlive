# Modular Component-Based Dashboard via Pluggable Card Registry

Beamline landing interfaces require distinct operational contexts for external researchers (upcoming beamtimes, dewar shipments, recent sessions, and user guides) versus beamline staff and operators (real-time station status, automounter robotics, active remote access sessions, incoming shipments, and local contact rosters). Rather than overriding upstream generic project templates with monolithic conditional templates or hardcoded views, we decided to implement a pluggable, registry-driven dashboard architecture (`mxlive.dashboard`) featuring an autodiscovering `CardRegistry`, encapsulated `DashboardCard` components with explicit visibility checks and per-request context memoization, and a role-dispatching root view. This design prevents unnecessary database queries, enables clean separation of user and staff operational concerns, allows independent testing of dashboard cards, and provides a responsive multi-column layout system that other station modules can extend without modifying core dashboard templates.
